# Release `v0.1.0`

## Highlights

- **Graduated `#![no_std]` Domain Core (`quota-core` `0.1.0`):**
  - Validated non-zero `Capacity` and `RatePerSec` newtypes plus `Remaining` balance wrapper.
  - `TokenBucket` (`TokenBucketQuota`) with exact integer-nanosecond refill, sub-token remainder preservation, idle burst clamping, `try_acquire`, `available_remaining`, `available_tokens`, and `available_at`.
  - Cross-target verification against bare-metal `thumbv7em-none-eabi` on Rust `1.100.0` (`edition = "2024"`) plus `#![no_std]` `semver_contract` trait/signature tests.
- **Wire Boundary Adapter (`quota-adapters` `0.1.0`):**
  - Strict `#[serde(deny_unknown_fields)]` wire DTOs (`PolicyConfigWire`, `AcquireRequestWire`, `AcquireResponseWire`) and stateful `QuotaJsonAdapter`.
- **Pure-Rust Governance & Release Automation (`xtask`):**
  - Derive-aware API surface lock (`api/quota-core.api`), strict 2-commit `Trust-Boundary` enforcement, pure-Rust `tar` + `flate2` archive packaging with offline unpacked consumer verification, 4-host `PreToolUse` safety hooks, `sync-branches`, and split `main-release` / `stable-publish` GitHub governance.

## Release Channel & Maintenance Lineage Policy

| Tag Pattern | Channel | GitHub `prerelease` | Required Gate | Lineage Requirement |
| --- | --- | --- | --- | --- |
| `vX.Y.Z-alpha.N` | `alpha` | `true` | Admin tag creation + CI + SLSA | `origin/main` (`Z == 0`) or matching `origin/release/X.Y` |
| `vX.Y.Z-beta.N` | `beta` | `true` | Admin tag creation + CI + SLSA | `origin/main` (`Z == 0`) or matching `origin/release/X.Y` |
| `vX.Y.Z-rc.N` | `rc` | `true` | Admin tag creation + CI + SLSA | `origin/main` (`Z == 0`) or matching `origin/release/X.Y` |
| `vX.Y.Z` | `stable` | `false` | Admin tag creation + `environment: stable-publish` | `origin/main` (`Z == 0`) or matching `origin/release/X.Y` (`Z > 0`) |

### `release/X.Y` Maintenance Branches

When `main` advances to `0.2.0` or `1.0.0`, maintainers branch `release/0.1` from `v0.1.0` to ship SemVer-compatible patch releases (`v0.1.1`, `v0.1.2`). `cargo xtask check-release-lineage` requires `Z > 0` patch tags to reside on the exact matching `origin/release/X.Y` branch (or `origin/main` only while `origin/main` is still on `X.Y.Z`), rejecting mismatched maintenance branches.
